# Nugaom AI Pick — ลำดับสร้างระบบเพื่อลดการรื้อซ้ำ

อัปเดตตามงานวันที่ 26 กันยายน: `/api/news` แสดงข่าวหุ้นไทยและหุ้นสหรัฐฯ ฝั่งละไม่เกิน 4 รายการจาก MarketDX ในเครื่องแล้ว; การเปิดให้สมาชิกทั่วไปเห็นยังต้องยืนยันสิทธิแสดงผล ดู [รายละเอียดแหล่งข่าว](news-data-integration.md) ขั้นถัดไปของสายข่าวคือแคชร่วมถาวรและผูกข่าวกับรหัสสินทรัพย์/ตลาดที่ถูกต้อง ก่อนนำข่าวไปประกอบผลสแกนหรือคะแนนใด ๆ

ตรวจจากโค้ดและ API ในเครื่องวันที่ 26 กันยายน 2026 เอกสารนี้เป็นลำดับงานปัจจุบันแทนส่วนจัด priority ใน `daily-workspace-review-2026-09-26.md` ซึ่งเขียนก่อนเพิ่มระบบบัญชี

## สถานะที่ยืนยันได้ตอนนี้

- UI ค้นหาสินทรัพย์, watchlist ในเครื่อง, กราฟ, อินดิเคเตอร์, Financial Check และเมนูทำงานระดับ prototype; ราคาและผลลัพธ์บางส่วนยังเป็น DEMO หรือไม่มีฟีด
- `/api/market-data` และกราฟ PTT 1D อ่าน OHLC จริงจาก Settrade ได้ในเครื่องวันที่ 26 กันยายน; สิทธิแสดงข้อมูลแก่สมาชิกบน production และความครอบคลุมทุกสินทรัพย์/ทุก timeframe ยังต้องยืนยัน
- `/api/us-bars` และกราฟหุ้นสหรัฐฯ 1D อ่าน OHLCV จาก FMP EOD ได้ในเครื่อง โดยใช้เฉพาะแท่งก่อนวันปัจจุบันตาม New York; ราคา quote แยกจากแท่งรายวัน และการเผยแพร่ production ยังปิดจนยืนยันสิทธิแสดงผล
- `/api/membership` ตอบ `configured:false` เพราะยังไม่มีค่า LINE Login และ secret ที่จำเป็นใน environment นี้ บัญชี LINE จริงยังไม่ได้เดินครบหน้าเว็บ
- มีระบบสมาชิก SQLite ในเครื่อง, ทดลอง 14 วัน, ตรวจเลขพอร์ต, โค้ดรายเดือน, อนุมัติรายเดือน และ server-side entitlement แล้ว แต่ยังไม่ได้ย้ายไป storage ถาวรสำหรับ production
- สมุดสัญญาณ, win rate, แจ้งเตือนอัตโนมัติ และแชตทีมยังเป็นตัวอย่าง ไม่ใช่ระบบที่มีผลจริงที่ตรวจย้อนกลับได้
- เมนูแผนสัญญาณมีฟอร์ม Entry/Stop/Target และคำนวณขนาดสถานะจากงบความเสี่ยง ใช้เป็นร่างแผนส่วนตัวในเบราว์เซอร์; ยังไม่ใช่สัญญาณอัตโนมัติหรือบันทึกถาวรข้ามเครื่อง

## ข้อตกลงที่ต้องล็อกก่อนเพิ่มฟีเจอร์

1. **MVP สัญญาณตลาดเดียวก่อน:** หุ้นไทยและ DR บนแท่งรายวัน 1D; หุ้นสหรัฐฯ 1D เปิดอ่านกราฟและอินดิเคเตอร์จาก FMP EOD ในเครื่องแล้ว แต่ยังไม่เข้าวงจรสัญญาณ/ผลลัพธ์จริง; TFEX, Forex และคริปโตอยู่ในเมนูสำรวจ/รอฟีดจนมีข้อมูลและสิทธิใช้งานครบ
2. **แหล่งข้อมูลและสิทธิ:** ยืนยันว่าฟีดใช้แสดงให้สมาชิก เก็บแท่ง และสร้างผลสัญญาณได้; แยกสถานะ `live / delayed / stale / unavailable` พร้อมเวลา `observedAt` และ `receivedAt`
3. **นิยามสัญญาณหนึ่งชุด:** ใช้เฉพาะแท่งที่ปิดแล้ว ระบุเวลาเข้า, ราคาเข้า, TP, SL, หมดอายุ, ค่าธรรมเนียม และกรณีแท่งเดียวแตะ TP กับ SL ก่อนเขียน win rate
4. **ฐานข้อมูลหลักหนึ่งแห่ง:** เลือก storage ถาวรและวิธีสำรองข้อมูลก่อนย้ายบัญชีหรือเพิ่ม signal ledger; ไม่ให้ localStorage หรือไฟล์ SQLite ชั่วคราวเป็นความจริงกลางของผลเทรด
5. **กติกาสมาชิก:** 14 วันเริ่มเมื่อแจ้งพอร์ตครั้งแรกและไม่เริ่มใหม่เมื่อแจ้งซ้ำ; กำหนดชื่อโบรกเกอร์แบบรหัสมาตรฐาน, ขั้นตอนยืนยันเจ้าของพอร์ต, นโยบายโค้ด/การชำระ และการแก้ข้อมูลส่วนตัว

## ลำดับลงมือและเกณฑ์ผ่าน

| ลำดับ | งาน | เหตุผลที่ต้องมาก่อน | เกณฑ์ผ่านก่อนเริ่มช่วงถัดไป |
| --- | --- | --- | --- |
| 0 | ตกลง 5 ข้อด้านบนและบันทึก data contract | UI, scanner, สถิติ และ billing จะอ้างนิยามเดียวกัน | มีตัวอย่าง payload ของ instrument, closed candle, scan run, signal, outcome, membership; กติกา versioned |
| 1 | ข่าว MarketDX ใช้งานในเครื่อง และเตรียมสิทธิ/แคชสำหรับเผยแพร่ | เปิดข้อมูลจริงที่ตรวจต้นทางได้ก่อนขยายหน้าจอ | หน้าข่าวแสดงแหล่งข่าวและเวลา; API ไม่เผยคีย์; จำกัดเครดิต; สิทธิ public display ได้รับการยืนยันก่อนเปิด production |
| 1.5 | ซ่อมและตรวจฟีด SET/DR | ไม่มีแท่งจริงก็ไม่มีสัญญาณที่ตรวจสอบได้ | `AUTH_FAILED` หาย; หุ้น SET, mai และ DR ตัวแทนอ่านแท่ง 1D ที่ปิดแล้วได้; มี freshness/source/venue; สัญลักษณ์ที่อ่านไม่ได้แสดง unavailable |
| 2 | ย้ายข้อมูลสมาชิกไปฐานถาวร + เดิน LINE จริงบน staging | บัญชีและ signal ledger ควรใช้ identity/storage ชุดเดียว | login/logout, trial, พอร์ต, แอดมิน, โค้ดและหมดสิทธิผ่าน browser→API→database; backup/restore ได้; API ปิดสิทธิเมื่อหมดอายุ |
| 3 | ทำ scanner กลยุทธ์เดียวแบบ deterministic | ต้องพิสูจน์คุณค่าหลักก่อนเพิ่มหลายร้อยรูปแบบ | ผลสแกนซ้ำจากข้อมูลและ rule version เดิมได้; บันทึก scan run, ตัวผ่าน/ไม่ผ่านและเหตุผล; ไม่สร้างสัญญาณบนข้อมูล stale/แท่งยังไม่ปิด |
| 4 | บันทึกสัญญาณถาวรและปิดผล | สถิติ, alert และ AI ต้องอ้าง record จริงเดียวกัน | ทุก signal มี ID, rule version, candle IDs, Entry/TP/SL; outcome worker บันทึก win/loss/open/expired/ambiguous/void; กดจากสถิติกลับไปแท่งหลักฐานได้ |
| 5 | จัดหน้าใช้งานทุกวัน + สแกนอัตโนมัติและแจ้งเตือน | เมื่อผลจริงเชื่อถือได้แล้วจึงส่งผู้ใช้ | Home แสดงสิ่งเปลี่ยนจากวันก่อนและคู่โปรด; งานสแกนตามเวลาไม่ซ้ำ; แจ้งเตือนมี opt-in, delivery status และลิงก์ signal เดียวกัน |
| 6 | เปิดรับสมาชิกแบบ pilot แล้วค่อยชำระอัตโนมัติ | ให้ลูกค้าจ่ายเมื่อฟีด/สัญญาณพร้อมและสิทธิไม่ผิดพลาด | pilot ใช้แอดมินตรวจชำระหรือโค้ดรายเดือน; เมื่อเลือกรับชำระออนไลน์แล้วจึงต่อ checkout, verified webhook, ใบเสร็จ, ยกเลิก/คืนเงิน, reconciliation |
| 7 | ขยายตลาด, AI, ข่าวรายสินทรัพย์, ชุมชน, EA/MT5 | ทุกตลาดเพิ่มกติกาเวลา, สิทธิข้อมูล, ค่าสัญญาและผลลัพธ์ต่างกัน | แต่ละตลาดผ่าน data + signal + outcome + entitlement contract เดียวกันก่อนเปิดเมนูเป็นฟีเจอร์จริง |

งานข่าวช่วง 1 ทำในเครื่องได้ทันที; การเผยแพร่ต้องผ่านสิทธิข้อมูลและแคชร่วมก่อน ส่วนช่วง 1.5 และ 2 ทำคู่ขนานได้ **หลัง** ตกลง storage และ data contract ในช่วง 0; ช่วง 3 ต้องรอฟีดราคาในช่วง 1.5; ช่วง 4 ต้องมีผลจากช่วง 3; ช่วง 5–6 ต้องใช้ signal/outcome จริงจากช่วง 4

## สิ่งที่ควรพักไว้ก่อน

- เพิ่มกล่อง/ปุ่ม/เอฟเฟกต์ภาพใหม่, คะแนน AI หรือคำว่า win rate ขณะยังไม่มีผลที่ตรวจย้อนถึงแท่งจริง
- ขยาย 6 ตลาดพร้อมกัน, สแกนรูปแบบหลายสิบชนิด, 3D/Flow/Alt Data, EA ส่งคำสั่ง, ชุมชน และระบบเครดิต ก่อน vertical slice แรกจบ
- เชื่อม payment gateway หรือเปิดโปรแพ็กเกจหลายระดับ ก่อนตัดสินสิทธิที่แต่ละแพ็กเกจได้จริงและยืนยันการต่ออายุครบวงจร

## งานถัดไปที่เล็กที่สุดแต่ปลดล็อกได้มากที่สุด

ยืนยันสิทธิแสดงข่าว MarketDX ต่อสมาชิกและทำแคชข่าวร่วมที่มีงบเครดิต จากนั้นเขียน data contract และกติกาปิดแท่ง/ปิดผลหนึ่งหน้า แล้วซ่อม `AUTH_FAILED` ของ Settrade สำหรับ PTT, หุ้น mai หนึ่งตัว และ DR หนึ่งตัว หากสิทธิแสดงผลเชิงพาณิชย์ยังไม่ยืนยัน ให้คงการทดลองไว้ในเครื่องและไม่ยกสถานะข้อมูลเป็น live บนเว็บสาธารณะ
