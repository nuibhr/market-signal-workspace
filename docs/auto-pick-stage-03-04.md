# AutoPick ขั้น 03–04 · 27 กันยายน 2026

> อัปเดตสูตรหุ้นไทย 29 ก.ย. 2026: scanner ใหม่ใช้ ORB 15m ตาม [กติกาสแกนตามข้อมูลที่ระบบมี](scanner-rules-2026-09-29.md). แผน `technical-plan-v1` เดิมที่บันทึกไว้ยังถูกติดตามด้วยกติกาเดิมจนจบสถานะ; รายละเอียดด้านล่างเป็นประวัติขั้น 03–04 ก่อนเปลี่ยนสูตร

## วงจรที่เพิ่มในโค้ด

- Scanner หุ้นไทยนำร่อง 8 ตัวจาก SET100 อ่านแท่ง Settrade 15m/1h/4h/1d และใช้ `technical-plan-v1` ตามขั้น 02
- ราคา Entry/TP/SL ของหุ้นไทยปัดตาม tick SET ในทิศทางอนุรักษนิยม แล้วคำนวณ R:R ใหม่; ถ้าต่ำกว่า 1.8 จะไม่ปล่อยสัญญาณ
- สแกนวันทำการ 10:15–11:15 น. กรุงเทพฯ เมื่อมีแท่ง 15m ของวันปัจจุบันที่ปิดแล้ว; ติดตามแท่งถึง 16:45 น. worker ตรวจเวลาทุก 30 วินาทีและบันทึกผลไม่ซ้ำในแต่ละช่วง 15 นาที จากนั้นส่งตรวจผลหากยังไม่ถึง TP1 หรือ SL เมื่อจบวัน
- ทุก symbol ในแต่ละรอบมี `CANDIDATE` หรือ `REJECTED` กับเหตุผล; ไม่ประกาศสัญญาณหากฟีดไม่ครบหรือแผนไม่ผ่าน
- แผนหนึ่งตัวต่อหนึ่ง symbol ต่อวันมี ID เดียว, rule version, เวลาแท่งหลักฐาน, entry, TP1, TP2, SL และสถานะ
- แจ้ง `ENTRY` เมื่อแท่ง 1H หลังเผยแพร่แผนปิดผ่าน trigger และราคาไม่ไกลจน R:R ต่ำกว่า 1.8; ราคา entry เป็นราคา **อ้างอิงของแท่งที่ปิด** ไม่ใช่ราคา fill ของลูกค้า
- ติดตาม TP1 และ SL จากแท่ง 15m ที่ปิดหลัง entry; ถ้าแตะทั้งคู่ในแท่งเดียวให้ `AMBIGUOUS`, ถ้าข้อมูลขาดช่วงให้ `REVIEW`, ถ้าไม่เข้าเงื่อนไขก่อน 12:30 ให้ `EXPIRED`
- Event และ scan run เก็บใน SQLite พร้อม idempotent ID. หน้าบ้านอ่าน `/api/auto-pick` ทุก 30 วินาทีและแสดง toast เฉพาะเหตุการณ์ใหม่ในขณะที่เปิดเว็บ
- `PICK_READY` คือแผนที่รอยืนยัน ไม่ใช่สัญญาณเข้า; ไม่ส่ง toast ให้ชวนเข้าก่อน trigger

## วิธีเปิดในเครื่อง

1. ตั้งค่า Settrade และ secret สมาชิกตาม README; ตั้ง `AUTO_PICK_ENABLED=true` และ `AUTO_PICK_RUN_SECRET` เป็นค่าสุ่มอย่างน้อย 32 ตัวอักษรใน `.env.local`
2. เปิดเว็บ `npm run dev` และเปิด worker แยกด้วย `npm run autopick:worker`; worker ต้องทำงานต่อเนื่องและเครื่องต้องไม่หลับ
3. เข้าสู่ระบบ LINE พร้อมสิทธิ trial/subscriber จึงอ่าน signal feed ได้; guest เห็นเฉพาะสถานะความพร้อม
4. `POST /api/auto-pick/run` ใช้ `Authorization: Bearer <AUTO_PICK_RUN_SECRET>` สำหรับ scheduler ภายนอกเท่านั้น; endpoint ไม่เปิดให้เบราว์เซอร์ของสมาชิกเรียก

## สถานะตรวจจริง 27 ก.ย. 2026

- Settrade login สำเร็จ และ PTT ได้ 100 แท่งครบทั้ง 15m, 1h, 4h และ 1d; ไม่มีแท่งถูกคัดทิ้งจาก parser ในชุดนี้
- ตรวจเวลาแท่ง 15m ของ PTT แล้วพบช่วงพักปกติ 12:15 → 13:45 ในฟีด จึงยกเว้นช่วงนี้จากการตัดสินว่าแท่งขาด
- `npm run build` ผ่าน; API `/api/auto-pick` ตอบสถานะความพร้อมและจำกัด feed ตามสิทธิสมาชิก
- worker ในเครื่องเปิดอยู่ แต่วันนี้เป็นวันอาทิตย์ จึงไม่มีสัญญาณเข้า/ออกจากตลาดสดให้ยืนยันจนกว่าจะถึงวันทำการ
- FMP intraday endpoint ของคีย์ที่ตั้งไว้ตอบ HTTP 402 สำหรับ AAPL 1h และ 15m จึงยังไม่ใช้ทำแจ้งเตือน Nasdaq-100

## ตรวจซ้ำ 28 ก.ย. 2026

- เปิด worker และให้ทำรอบจริงระหว่างเวลาตลาดได้สำเร็จ; รอบหลังช่วงคัดหุ้นทำงานติดตามและบันทึกผลลง SQLite. วันนี้ worker เริ่มหลัง 11:15 น. จึง **พลาดรอบคัดหุ้นเช้า** และหน้าเว็บแสดงสถานะนี้ตรง ๆ. การพักเครื่องทำให้ worker ข้ามช่วงเวลาได้ จึงต้องย้ายไปเครื่องที่ทำงานต่อเนื่องก่อนเปิดให้ลูกค้าใช้จริง
- `npm run probe:autopick` เล่นซ้ำแบบอ่านอย่างเดียว ณ 11:14 น. ด้วยข้อมูลแท่งวันนี้: หุ้นนำร่อง 8/8 ตัวมีแท่ง 15m/1h/4h/1d อย่างละ 100 แท่ง และผ่านขั้นอ่านข้อมูล/คำนวณแผนโดยไม่มีคำขอที่ล้มเหลว; วันนี้ 0 ตัวผ่านเกณฑ์ จึงยังไม่สามารถยืนยันทางเดินแจ้งเข้า/ถึงเป้า/ตัดขาดทุนจากตลาดสด
- หากช่วงคัดหุ้นไม่มีแท่ง 15m ที่สดพอ ระบบบันทึกเป็นปัญหาฟีด ไม่แสดงรอบสแกนว่าแข็งแรงทั้งที่ข้อมูลไม่ครบ
- หุ้นสหรัฐฯ มีแท่งรายวันจาก FMP; intraday ยังไม่พร้อมใช้กับ AutoPick

## เพิ่มระบบหุ้นสหรัฐฯ แบบ EOD · 28 ก.ย. 2026

- เพิ่ม scanner แยกตลาด `us` ซึ่งอ่าน Nasdaq-100 101 securities จาก snapshot ของ Nasdaq และใช้ FMP EOD 1D เท่านั้น ไม่ใช้ FMP intraday หรือ quote snapshot เป็นแท่ง
- หลัง NYSE/Nasdaq ปิด worker รอจน FMP ส่งแท่งวันที่ปัจจุบันครบ แล้วสแกน 101 รายชื่อแบบจำกัด concurrency; ถ้าราคา EOD ยังไม่มาให้คงสถานะรอ/แจ้งข้อมูลล่าช้า ไม่สร้างแผนจากวันก่อน
- กติกานำร่อง `us-eod-breakout-v0.1-unvalidated` แสดงแผน LONG ที่ผ่านแนวโน้ม/สภาพคล่อง/ATR/R:R และรอแท่ง D1 วันถัดไปปิดเหนือจุดยืนยัน; Entry/TP/SL อาจแจ้งหลังตลาดปิด
- `TARGET`/`STOP` ตรวจช่วง High/Low ของแท่ง D1; หากแท่งเดียวแตะทั้งสองระดับจะส่ง `AMBIGUOUS`. ผลนี้เป็นระดับราคาอ้างอิง ไม่ใช่ fill ของบัญชี
- Nasdaq current constituent API และ FMP bulk EOD ตอบ HTTP 402 ด้วย key ที่ตรวจในเครื่อง; จึงไม่ได้พึ่ง endpoints เหล่านั้นใน worker. Static index snapshot ลงวันที่ 22 มิ.ย. 2026 ต้องทบทวนเมื่อ Nasdaq เปลี่ยนรายชื่อ
- Production ยังต้องมี `FMP_DISPLAY_RIGHTS_CONFIRMED=true`, SQLite/worker ที่ทำงานถาวร และ `AUTO_PICK_US_ENABLED=true`; สิทธิแสดงกราฟกับสิทธิแสดงสัญญาณ/จัดเก็บข้อมูลอาจเป็นคนละขอบเขต

รายละเอียดกติกาและข้อจำกัดอยู่ใน [US EOD AutoPick](us-autopick-eod.md).

## ขอบเขตที่ยังปิดอยู่

| ตลาด | สิ่งที่ยังขาดก่อนเปิด autopick |
| --- | --- |
| TFEX | มี OHLC สำหรับกราฟแล้ว; ก่อน AutoPick ต้องมีกรอบเวลาเหมาะกับ ORB, ยืนยันสัญญา active/rollover, tick, multiplier, ต้นทุน/หลักประกัน และสิทธิข้อมูล |
| Forex 19 รายการ | ฟีดแท่งและ bid/ask/spread ของโบรกเกอร์ที่ใช้เทรดจริงพร้อมสิทธิข้อมูล; Twelve Data composite ใช้สำรวจได้แต่ไม่ใช่ราคา fill |
| Nasdaq-100 | รายชื่อสมาชิกดัชนีปัจจุบันที่ตรวจได้, intraday OHLC, market calendar/ช่วงเวลา New York, และสิทธิแสดงผล/จัดเก็บ |

การแจ้งเตือนของผลิตภัณฑ์นี้อยู่ **ในเว็บเท่านั้น**: เก็บ event บนเซิร์ฟเวอร์, แสดง toast ขณะหน้าเว็บเปิดอยู่ และมีรายการเหตุการณ์ให้สมาชิกย้อนอ่านเมื่อกลับมาเปิดเว็บอีกครั้ง ไม่ส่งข้อความหรือ push เมื่อปิดเว็บ การเปิดใช้งานจริงต้องตรวจว่า event ไม่ซ้ำ อ่านย้อนหลังได้ตามสมาชิก และระบุเวลาต้นทาง/เวลารับข้อมูลชัดเจน

การเปิด production ต้องย้าย SQLite ไปเซิร์ฟเวอร์และ volume ที่ถาวรและสำรองข้อมูลได้ พร้อมตั้ง `AUTO_PICK_PERSISTENT_SERVER_CONFIRMED=true` และยืนยันสิทธิ `SETTRADE_DISPLAY_RIGHTS_CONFIRMED=true` ก่อน ขณะนี้ไม่ได้เปิดบน hosting แบบ filesystem ชั่วคราว

สถิติ win rate ที่มีอยู่เดิมยังเป็น DEMO. Ledger ใหม่ไม่ถือว่าเป็นการซื้อขายจริงและยังไม่รวมค่าคอมมิชชัน สเปรด สลิปเพจ และ corporate actions. ต้องแยกผล `AMBIGUOUS`/`REVIEW`/`EXPIRED` ออกจาก win rate เสมอ
