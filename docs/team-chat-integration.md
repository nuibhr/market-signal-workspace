# ช่องทางคุยกับทีม Nugaom

## ทางเลือกที่แนะนำสำหรับเฟสแรก

ให้สมาชิกเข้าสู่ระบบด้วย LINE แล้วคุย **ภายในเว็บ** โดยเลือกหัวข้อ “บัญชีและแพ็กเกจ” หรือ “ข้อมูลและแผน” ระบบส่งเข้ากล่องงานของทีมการตลาดหรือทีมวิเคราะห์ตามหัวข้อ สมาชิกกลับมาอ่านคำตอบและสถานะได้ในเว็บ ข้อความใหม่ใช้ป๊อปอัปขณะเปิดหน้าเว็บเหมือนระบบ AutoPick

หน้าคุยปัจจุบันเป็น DEMO และไม่ได้ส่งข้อความให้ทีม จึงต้องทำส่วนต่อไปนี้ก่อนเปลี่ยนปุ่มเป็น “ส่งจริง”:

1. ฐานข้อมูลถาวรสำหรับ `conversation`, `message`, `assignment` และ `read_receipt` ผูกกับสมาชิกจาก LINE Login; เก็บเวลาและผู้ส่งทุกข้อความ
2. API ฝั่งสมาชิกสำหรับเปิดหัวข้อ อ่านประวัติ และส่งข้อความ ตรวจ session, จำกัดความถี่และขนาดข้อความทุกครั้ง
3. กล่องงานของทีมพร้อมบทบาท `marketing`, `analyst`, `admin` ให้เห็นเฉพาะหัวข้อที่รับผิดชอบ ตอบกลับ ย้ายทีม และปิดเรื่องได้
4. สถานะ “รับเรื่องแล้ว / กำลังตรวจ / ตอบแล้ว” พร้อมตัวนับยังไม่อ่านและการแจ้งเตือนบนเว็บ
5. ไม่แสดงเลขพอร์ตเต็มในบทสนทนา; ใช้ข้อมูลสถานะสมาชิกที่เซิร์ฟเวอร์มีอยู่แล้ว และให้แอดมินตรวจเลขพอร์ตในหน้าสิทธิสมาชิกเดิม

เริ่มด้วยการอ่านคำตอบใหม่ทุก 15–30 วินาทีแบบเดียวกับ AutoPick ก่อน หากจำนวนผู้ใช้มากจึงเปลี่ยนเป็น SSE หรือ WebSocket โดยใช้เหตุการณ์ในฐานข้อมูลชุดเดิม

## LINE Official Account เป็นช่องทางเสริม

LINE Login ใช้ยืนยันตัวตน ส่วนการแชตผ่าน LINE ต้องมี **LINE Official Account + Messaging API** แยกต่างหาก หากต้องการให้บทสนทนา LINE ปรากฏในกล่องงานเดียวกัน ให้สร้างช่อง LINE Login และ Messaging API ภายใต้ provider เดียวกัน, เชื่อม OA กับช่อง Login, เปิด webhook แบบ HTTPS และตรวจลายเซ็นทุกข้อความก่อนบันทึก จากนั้นส่งต่อข้อความให้ทีมตามหมวดที่ลูกค้าเลือก

ควรเปิดช่องทาง LINE OA หลังกล่องงานในเว็บทำงานจริง เพราะทีมต้องมีที่รับ ตอบ และติดตามงานก่อน ข้อความ AutoPick ยังแจ้งเฉพาะในเว็บตามข้อกำหนดของผลิตภัณฑ์

แหล่งอ้างอิง: [LINE Login + OA](https://developers.line.biz/en/docs/line-login/link-a-bot/), [User ID ภายใต้ provider](https://developers.line.biz/en/docs/messaging-api/getting-user-ids/), [Webhook และการตรวจลายเซ็น](https://developers.line.biz/en/docs/messaging-api/receiving-messages/)
